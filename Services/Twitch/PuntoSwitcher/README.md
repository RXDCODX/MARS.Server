# PuntoSwitcher для Twitch-чата

## Что изучено из готовых кейсов

Ниже — источники и практики, которые легли в основу базовой реализации:

1. `alexfrmn/ruswitch` (Windows, RU/EN)
   - Большие словари RU/EN
   - Автообучение пользовательского словаря
   - Исключение процессов (например, password manager)
   - Undo последнего исправления

2. `rshagiev/punto-switcher` (macOS, RU/EN)
   - Архитектура из независимых модулей: трекер слова, конвертер раскладки, доступ к тексту
   - Защита от ложных срабатываний
   - Явные boundary-правила (разделители слов, спецклавиши)

3. `DKunin/keyboard-layout-switch` (lightweight library)
   - Минималистичный посимвольный RU/EN mapping
   - Простая интеграция как pure-функция без UI

4. Официальная документация Twitch Chat
   - Нужно учитывать лимиты отправки сообщений и не спамить исправлениями
   - Для production-бота важны throttling и anti-flood механики

## Базовые best practices для Twitch PuntoSwitcher

1. Не исправлять всё подряд
   - Пропускать команды (`!`, `/`, `.`), ссылки, упоминания и техтокены
   - Пропускать короткие токены

2. Делать исправление по токенам, а не всей строкой целиком
   - Сохранять пунктуацию и оформление
   - Менять только подозрительные части

3. Использовать эвристики уверенности
   - Проверка доминирующего алфавита
   - Сравнение гласности слова до/после конвертации

4. Защищать known-good токены
   - Белый список emote/шаблонов чата (например `KEKW`, `PogChamp`)

5. Держать сервис идемпотентным
   - Если уверенности недостаточно, возвращать исходный текст

## Что уже реализовано в этом проекте

- `IPuntoSwitcherService` + `PuntoSwitcherService`
- RU/EN посимвольный конвертер с сохранением регистра
- Токенизация и точечная замена только безопасных кандидатов
- Базовые Twitch-эвристики (команды/URL/упоминания/эмоуты)
- Подключение сервиса в `HighlitedMessage` перед отправкой в SignalR

## План развития (roadmap)

1. Добавить словари частотных слов RU/EN (in-memory)
   - Поднимать confidence, снижать false-positive

2. Добавить пользовательский словарь из БД
   - Do-not-fix список и auto-learn по подтверждённым исправлениям

3. Ввести антифлуд-политику для автоответов (если понадобятся)
   - Cooldown на пользователя и канал

4. Добавить телеметрию качества
   - Метрики: `attempted`, `fixed`, `skipped`, `false-positive-report`

5. Добавить unit-тесты на наборы кейсов
   - RU->EN, EN->RU, mixed-layout, emotes, links, commands

6. Добавить конфиг в `appsettings`:
   - `Enabled`, `MinTokenLength`, `Aggressiveness`, `ProtectedTokens`
