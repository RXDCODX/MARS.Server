# Changelog - RxdcodxViewersService

## Версия 3.1.0 - Автоматическая актуализация данных при старте

### ✨ Новые возможности

#### Актуализация данных при запуске приложения

- **Автоматическая актуализация** - при запуске приложения автоматически актуализируются данные о фоловерах, модераторах и VIP
- **Удаление отписавшихся** - пользователи, которые отписались от канала, автоматически удаляются из БД
- **Обновление статусов** - автоматическое обновление статусов модератор/VIP для всех пользователей
- **Публичный API** - метод `ActualizeFollowersAsync()` для ручного запуска актуализации

#### Новые методы

- `ActualizeFollowersAsync()` - публичный метод для ручной актуализации данных
- `ActualizeFollowersDataAsync()` - приватный метод актуализации при старте
- `DeleteFollowersAsync(ICollection<string>)` - массовое удаление пользователей из БД

### 🔧 Улучшения

#### Автоматизация

- Актуализация запускается автоматически через `BackgroundService.ExecuteAsync`
- Происходит при запуске приложения, после инициализации кеша
- Не требует дополнительных настроек

#### Надежность

- Обработка случаев когда пользователи отписываются
- Обработка изменений статусов (модератор → обычный фоловер и т.д.)
- Логирование всех изменений для отслеживания

### 📚 Документация

- Обновлен интерфейс `IRxdcodxViewersService`
- Добавлены XML-комментарии для новых методов
- Обновлен CHANGELOG

### 🔄 Обратная совместимость

- Все существующие методы работают как прежде
- Добавлен новый метод в интерфейс `IRxdcodxViewersService`

### 🚀 Использование

```csharp
// Автоматически выполняется при запуске приложения
// Для ручного запуска:
await _viewersService.ActualizeFollowersAsync();
```

## Версия 3.0.0 - Database-First Cache Architecture

### ✨ Новые возможности

#### Database-First Cache

- **База данных как кеш** - убран `ConcurrentDictionary`, БД используется как основное хранилище
- **Персистентность данных** - данные сохраняются между перезапусками приложения
- **Упрощенная архитектура** - нет необходимости в синхронизации между кешем и БД
- **Автоматическое восстановление** - при запуске сервис загружает данные из БД

#### FollowerInfo Entity

- **Расширенная модель данных** `FollowerInfo` для работы с фоловерами
- **Дополнительные поля**:
  - `LastUpdated` - время последнего обновления
  - Методы для проверки актуальности данных
- **Совместимость** с `ChannelFollower` через методы преобразования
- **Оптимизированные методы** - улучшенная производительность

#### Новые методы API

- `GetAllFollowersInfo()` - получение фоловеров как `FollowerInfo`
- `GetFollowerInfo(userId)` - информация о конкретном фоловере
- `ClearFollowersCache()` - очистка БД (асинхронный)
- `GetUsersWithoutAvatarsAsync()` - получение пользователей без аватарок
- `GetUsersWithoutAvatarsCountAsync()` - подсчет пользователей без аватарок
- `UpdateMissingAvatarsAsync()` - обновление аватарок для пользователей без них

### 🔧 Улучшения

#### Производительность

- Убраны все `lock` блокировки и `ConcurrentDictionary`
- Использование БД как основного хранилища

#### Безопасность

- Потокобезопасные операции с БД через Entity Framework
- Улучшенная обработка ошибок
- Атомарные операции обновления через транзакции

#### Удобство использования

- **Автоматическое обновление аватарок** - поиск и обновление аватарок для пользователей без них
- **REST API endpoints** для работы с аватарками
